# External model workflow — linked GLBs

This edition ships with seven **real, separate binary `.glb` models**, rebuilt from the procedural geometry in `world.js` at local scene origins. They are loaded **by default** into the existing 56.47-second flythrough. The original procedural geometry remains available as a fallback.

The exported geometry is *not* a photogrammetric scan or a Tripo-generated model. Surface materials are re-created as standard glTF PBR materials. Procedural particle fields, glow sprites, and moving beams are **not baked into the GLBs**; those animated effects continue to render from `world.js`. For the highest-fidelity export of the browser's exact Three.js geometry, use **Export selected GLB** or **Export all 7 models** in the project Inspector.

The seven GLBs are stored at `assets/models/`. The scene origins above are automatically applied by `world.js`; **do not add these world X offsets to the model in Blender**. Within each GLB, positions are in local scene coordinates and **Y is up**.

## Edit and relink

1. Open `assets/models/pcb.glb` (or any other GLB) in **Blender** (File → Import → glTF 2.0). Use mesh edit mode to change objects. Avoid moving the entire object hierarchy; preserve scale and local origin when possible.
2. Export to **glTF Binary (.glb)** (File → Export → glTF 2.0). Overwrite the original `assets/models/pcb.glb` (keep a backup first).
3. In the running Three.js studio, click **Reload linked GLBs from folder**, or refresh your browser. Your edits will appear at the exact same timecode and world position. **Camera keys, cuts and text overlays are unchanged.**
4. To test a file before overwriting: choose a slot and click **Preview replacement GLB…**. This loads it into the live scene temporarily. It will only persist when you copy the GLB to `assets/models/`.

To replace a model generated by **Tripo**, export as GLB. The Tripo model will generally have a different size and origin. Adjust `position`, `rotation` (radians), and `scale` arrays for the relevant model entry in `assets/models/manifest.json`, then reload.

> Example: `"scale": [2, 2, 2]` doubles the imported mesh; `"position": [0, 1, 0]` shifts it upward one scene unit *relative to its existing flythrough world offset*.

## Export again from the original procedural objects

The **Inspector → Project settings → External model library** has an exporter for the current browser-native Three.js models:

- **Export selected GLB** downloads one model (model-local origin; no baked world offset).
- **Export all 7 models (ZIP)** packs all seven `.glb` files and an enabled `manifest.json` under `assets/models/`. Unzip that archive into the *project root* to override the editable starter GLBs. Note: this export may take a few seconds for the server hall.
- **Restore procedural model** temporarily switches one slot back to original procedural geometry.

The exporter skips transient effects (particles, glow sprites, beam meshes). This is intentional and keeps the GPU effects driven by the scene timeline. The crystal lattice rotation and rotating garnet gem are preserved via the stable node names `lattice_spin` and `garnet_crystal`.

## Troubleshooting

- **Cannot see changes?** Confirm you exported to the exact path in `assets/models/manifest.json`; Chrome can cache assets (the reload button adds a cache-busting query). Check for failures in the browser console; missing/invalid GLBs fall back to procedural models automatically.
- **Wrong position/size?** Apply transforms in Blender, then adjust the manifest's relative `position`, `rotation`, and `scale` fields. Never bake scene global X offsets into the GLB itself.
- **Materials differ?** glTF PBR materials preserve base color and metallic/roughness but specialized shader effects (additive glow, glass transmission behavior) may look different in Blender versus WebGL. The independent Three.js effects remain procedural.
- **Animation lost?** `atoms` must contain a node named `lattice_spin` and `optics` must contain `garnet_crystal` for their original rotation hooks to continue after replacing the GLB.
- **Your editor cannot export glTF?** Import/edit in Blender and export GLB from there; Tripo's GLB export works as a replacement if the local coordinate system and scale are accounted for.

### Important

This does not perform live two-way synchronization with Blender. Changes written to local files are picked up when the application reloads its GLBs. The browser cannot modify source project files directly without explicit filesystem permissions.
